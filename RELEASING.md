# Выпуск RevEx Desktop

Обновляется только десктоп. При запуске установленного приложения проверяются
публичные стабильные релизы `DenisFazlul/RevEx.Desktop`. Пользователь выбирает
«Обновить» или «Продолжить без обновления». Скачивание начинается только после
согласия. При недоступности GitHub или таймауте проверки открывается текущая версия.
Закрытие окна предложения равнозначно отказу. Во время скачивания отказ отменяет
скачивание и продолжает запуск после его остановки. Ошибка скачивания позволяет
повторить попытку или использовать текущую версию.

## Выпуск через сайт GitHub

1. Отправьте изменения кода в `main`.
2. Откройте Actions → Desktop release → Run workflow.
3. Выберите `main`, введите новую версию, например `1.0.0`, и запустите workflow.
4. Дождитесь успешного завершения всех сборок.
5. Откройте Releases: workflow создаст **черновик** `RevEx 1.0.0` с файлами
   Windows x64, macOS Intel и macOS Apple Silicon.
6. Проверьте установщики, отредактируйте описание изменений и нажмите Publish release.
   Не отмечайте релиз как prerelease: такие версии десктоп не предлагает.

Сборки используют одну версию для приложения и пакетов; версии должны возрастать.
Для изменения исходников не требуется вручную редактировать версию в `.csproj`.
Не запускайте повторно выпуск уже существующей версии: используйте новую версию.
Черновик не виден updater, поэтому неполные или непроверенные сборки не предлагаются.
Первый выпуск устанавливается вручную. Обновления доступны начиная с установленной
версии, уже содержащей Velopack; старые сборки без updater сами обновиться не смогут.

## Альтернатива: выпуск по тегу

Из корня Git-репозитория `Desktop/RevEx.Desktop`:

```bash
git push origin main
git tag v1.0.1
git push origin v1.0.1
```

Это запускает тот же workflow и создаёт черновик. Перед тегом убедитесь, что нужные
изменения закоммичены. Публикуйте черновик после проверки.

## Какие файлы нужны

Workflow прикрепляет установщики, portable-пакеты, `.nupkg` и
`releases.win-x64.json`, `releases.osx-x64.json`, `releases.osx-arm64.json`.
Не удаляйте `.nupkg` и `releases.*.json`: они нужны updater.
Канал сохраняется в установленном пакете, поэтому приложение получает обновления
для своей ОС и архитектуры. Пакуется только `RevEx.Desktop.csproj` и его зависимости;
отдельные приложения коннекторов не выпускаются этим workflow.

## Подпись и проверка

Сейчас сборки **без сертификатов подписи и Apple notarization**. Windows SmartScreen
и macOS Gatekeeper могут предупреждать или блокировать установку. Для публичного
распространения нужны отдельная настройка сертификатов и секретов Actions; их нет
в репозитории, поэтому подпись не имитируется.

Перед публикацией проверьте реальное обновление A → B на Windows и обеих архитектурах
macOS: предложение, отказ, скачивание, отмена, ошибка сети и перезапуск новой версии.
После отказа рабочее пространство и авторизация должны запускаться нормально.
При обычном `dotnet run` приложение не установлено через Velopack и проверка пропускается.

## Разработка

Версии NuGet `Velopack` и инструмента `vpk` в workflow должны совпадать.
Настройки проверки находятся в секции `Updates` файла `appsettings.json`.
Токен GitHub в десктоп не встраивается; репозиторий релизов должен оставаться публичным.
Смена видимости на private потребует отдельного публичного хранилища релизов.

Проверка сборки:

```bash
dotnet build RevEx.Desktop.sln --disable-build-servers -m:1
```
