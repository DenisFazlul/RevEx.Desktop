# Формы и модели интерфейса

Разметка и взаимодействие с окнами находятся в `Views`. Данные формы, проверка ввода
и команды находятся в `ViewModels`. Запросы API и работа с коннекторами остаются
в существующих сервисах. Над каждой моделью есть короткое описание её назначения.

## Общие модели

| Основа | Для чего использовать |
| --- | --- |
| `ViewModelBase` | Наблюдаемые свойства небольшого элемента интерфейса. |
| `AsyncViewModelBase` | Загрузка, сохранение, сообщения и ожидаемые ошибки. `RunLoadAsync` и `RunSaveAsync` завершают состояние операции в `finally`. |
| `WorkspaceTabViewModel` | Рабочая вкладка: заголовок, выбор, безопасная активация и освобождение ресурсов. |
| `DialogViewModel<TResult>` | Диалог, возвращающий результат заданного типа. Команда отмены и событие закрытия не зависят от Avalonia. |
| `TextEditorViewModel<TResult>` | Текстовый ввод с общей проверкой обязательности и максимальной длины. |
| `SelectionDialogViewModel<TItem>` | Выбор одного элемента из списка и подтверждение выбора. |
| `FilterItemViewModel` | Название и признак выбора категории или тега. |

`TagEditorViewModel` и `TagGroupEditorViewModel` используют общую проверку текста,
но сохраняют собственные результаты и проверки. `CatalogSettingsViewModel` хранит
отдельный черновик фильтров: отмена не изменяет каталог, подтверждение применяет выбор
одним обновлением поиска.

## Общие представления

`DialogWindow` подписывается на запрос закрытия модели, возвращает результат
вызывающему экрану и снимает подписки при закрытии. Занятый диалог нельзя закрыть
посередине операции. Если модель реализует `IDisposable`, окно освобождает её ресурсы.

`LocalFilePicker` открывает выбор одного файла и возвращает `SelectedLocalFile`
с именем и локальным путём. Отмена возвращает `null`. `ViewContext.TryGetContext`
находит модель и окно-владельца для дочернего диалога.

`OperationFeedbackView` показывает прогресс, результат и ошибку из `AsyncViewModelBase`.
`RevitFamilyReadResultView` показывает метаданные семейства, список типоразмеров
в комбобоксе и параметры выбранного типа в раскрывающихся группах. Группы изначально
свёрнуты, объединяются по `GroupId` и показывают локализованный `GroupName`.
Параметры старых метаданных без группы попадают в «Прочее».
Категория семейства берётся из `RevitCategory`, отдельно от категории каталога.
При импорте ответ старого коннектора с полем `Category` приводится к `RevitCategory`
перед отображением и сохранением метаданных файла.
Для повторного использования передайте
в `DataContext` модель `RevitFamilyReadResultViewModel`, а в её `Family` —
`RevitFamilyReadResult`. Замена семейства выбирает первый тип и обновляет параметры;
`null` очищает просмотр. Компонент используется в окне добавления RFA.
Существующие `FormFieldTheme`, `DialogHeaderTheme` и `PageHeaderTheme` отвечают
за повторяющееся оформление полей и заголовков.

## Крупные экраны и жизненный цикл

`ContentDetailsViewModel` разделена на тематические файлы: основной хранит состояние
карточки; `Versions` работает с версиями и файлами; `Editing` — с полями карточки;
`Tags` — с тегами; `Loading` — с передачей файлов коннектору; `PublishStatus` —
с изменением статуса публикации. На вкладке «Версии» рядом с датой показана платформа
и выбор «Черновик / Готов / Снят». Кнопка «Сохранить статус» отправляет отдельный запрос,
не меняя другие поля версии. Выбор и кнопка доступны только при праве редактирования;
во время сохранения редактирование блокируется. Вспомогательные модели
строк и результаты диалогов находятся в отдельных файлах.

При закрытии вкладки `MainViewModel` вызывает её `Dispose`. Каталог отменяет поиск
и освобождает превью; очередь загрузок снимает подписку на изменения задач.
При закрытии главного окна освобождаются все оставшиеся вкладки.

Новые вкладки регистрируются в `WorkspaceTabFactory` и `MainMenuProvider`.
Окно импорта RFA запускается из вкладки «Добавление контента». Особенности Revit
относятся к процедуре импорта, а общая модель хранения файлов и JSON-метаданных
остаётся независимой от формата.
В начале окна коннектор выбирается в комбобоксе из текущего реестра. Список обновляется
при подключении и отключении коннекторов, сохраняя выбор по идентификатору экземпляра.
Первый коннектор выбирается автоматически; пока список пуст, кнопка «Открыть» недоступна.
Открытие окна не запускает выбор файла или чтение: только кнопка «Открыть» показывает
выбор RFA, после которого проверяются команды выбранного коннектора и читается семейство.
Если выбранный коннектор не поддерживает чтение, форма показывает ошибку без подбора другого.
Кнопка «Открыть» позволяет выбрать ровно один RFA и несколько вспомогательных CSV или IFC.
Список файлов отображается в форме. Рабочие копии всех выбранных файлов создаются до чтения,
но команда чтения коннектора получает только RFA. В новую версию загружаются RFA с ролью
`primary` и метаданными семейства, CSV — с ролью `lookup-table`, IFC — с ролью `attachment`,
без метаданных RFA. Версия получает платформу `Revit` и статус публикации `Draft`
из доменных перечислений. Повторное сохранение после сбоя сверяет уже загруженные
вспомогательные файлы, чтобы не создавать дубликаты.

## Проверка изменений

```powershell
dotnet build RevEx.Desktop.sln -c Release
dotnet run --project tests/DomainUiChecks -c Release
dotnet run --project tests/StartupUpdateChecks -c Release
```

Проверки охватывают валидацию диалогов, результат и отмену, блокировку закрытия
во время операции, освобождение ресурсов, применение фильтров, операции с тегами
и существующий поток импорта RFA через TCP-коннектор.
