# Сборки для внутреннего backend

После merge или push в `realese` Actions → Desktop installers собирает Windows x64,
macOS Intel и Apple Silicon через Velopack 1.2.161. Код приложения и `vpk` используют
одну версию SDK. Версия поставки — `1.0.<номер запуска workflow>`.

Обновите `packaging/release-notes.md` перед выпуском. Дождитесь успешного завершения
всех платформ и задания archive. Скачайте артефакт `RevEx-Desktop-Release-<version>`:
распакуйте **внешний ZIP GitHub Artifacts**. Внутри находится
`RevEx-Desktop-Release-<version>.zip` — именно его загружает администратор во frontend.

Архив содержит release.json, три установщика, три полных .nupkg и три
releases.<platform>.json. Отдельные исходные артефакты платформ доступны для диагностики.
Backend принимает один полный релиз без предыдущих версий и дельта-пакетов.

Установщики теперь создаёт Velopack. Старые скрипты Inno Setup и ручной упаковки
macOS сохранены для истории, но не используются для поставки с автообновлением.
Старые приложения без Velopack требуют первой ручной переустановки через frontend.

В установленном приложении проверка выполняется до входа и запуска коннекторов.
Если сервер ещё не имеет активного релиза, рабочее пространство не открывается.
Адрес backend можно изменить в стартовом окне. При запуске через IDE проверка
пропускается, поскольку отсутствует управляемая установка.

Релизы пока без Developer ID, notarization и подписи Windows. Для регламентированной
поставки настройте сертификаты и подпись в CI; для закрытого контура на macOS также
прикрепите notarization ticket. Ad-hoc подпись не подтверждает издателя.

Перед поставкой проверьте A → B, отказ при совместимой версии, обязательное
обновление, смену адреса, ошибку сети и сохранение настроек на каждой платформе.
Downgrade применяется только после выбора пользователя; предварительно убедитесь,
что локальные настройки совместимы со старой версией.

Проверки стартового решения без установки обновления:

```bash
dotnet run --project tests/StartupUpdateChecks/StartupUpdateChecks.csproj
```

Они покрывают совпадающую, совместимую и несовместимую версию, отказ пользователя,
недоступный backend, некорректный диапазон и внешний источник обновления.
